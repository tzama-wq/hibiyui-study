# ひびゆいFC サッカーがくえん

小2(ゆいと)・小4(ひびと)向けの予習復習PWA。サッカー風ゲーミフィケーション付き。

## 動かす
```
npm start     # http://localhost:8080
npm test      # 出題ジェネレーターの検算(1万8千問)
```

## 構成
- `gen.js` … 算数の出題。答えはコードで計算。誤答選択肢に「つまずき原因タグ」付き
- `app.js` … 画面・ポイント・ランク・かくれステージ・パパにきく
- 保存先は各端末の localStorage(兄弟それぞれのスマホで別々に記録)

## 公開(GitHub Pages)
リポジトリの Settings → Pages → Branch: main / root を選ぶ。
URL をスマホで開き、「ホーム画面に追加」するとアプリとして使える。

## これから
- 国語・生活・理科・社会 … Gemini で毎朝生成(GitHub Actions)→ `data/daily/` に JSON
- 学校の単元は「パパの へや」で手動調整できる

## きょうだい共有(ランク・ゴール数を お互いに見る)
別々のスマホでも相手の記録が見えるように、無料の Firebase Realtime Database を使う。共有するのは名前・ランク・ゴール数・日数だけ。

1. https://console.firebase.google.com でプロジェクトを作る(Googleアナリティクスは不要)
2. 「Realtime Database」→「データベースを作成」(ロケーション: シンガポール `asia-southeast1` など)
3. 「ルール」タブを次に置き換えて公開
   ```json
   {
     "rules": {
       "hibiyui": {
         "$code": {
           ".read": true,
           ".write": true,
           "$kid": { ".validate": "newData.hasChildren(['xp','goals'])" }
         }
       }
     }
   }
   ```
   `hibiyui` の直下には読み取り権限がないので、**家族コードを知らない人は一覧も見られない**(コードは推測されにくい長さにする)。
4. データベースのURL(`https://〇〇-default-rtdb.〇〇.firebasedatabase.app`)をコピー
5. アプリの「パパの へや」→「きょうだいと つなぐ」にURLを入れ、「コードを つくる」→「ほぞん」
6. 「こども用リンクを コピー」して、ひびと・ゆいとのスマホで開く(同じ設定が入る)

開発用: `node scripts/mock-db.mjs`(模擬DB、http://localhost:8787)に向ければ、Firebaseなしで動作確認できる。

## 国語(漢字)を Gemini で毎朝つくる
- `data/kanji.json` … 学年別漢字配当表(1〜4年)。`node scripts/fetch-kanji.mjs` で作成済み
- `data/kokugo-pool.json` … 出題プール。最初は手書きのシード(`node scripts/seed-kokugo.mjs`)、以降は毎朝ふえる
- `scripts/generate-kokugo.mjs` … Gemini に作らせて、**コードで検査してから**プールに追加

**AIの出力を信用しないための検査**(`scripts/lib/kokugo.mjs`)
1. 問題文・解説に、その学年で習っていない漢字があれば不採用(漢字表で機械的に判定)
2. 読みがひらがなだけか、選択肢が重複していないか等の形式チェック
3. 別の呼び出しで同じ問題を解かせ、答えが一致しなければ不採用(二重検算)

**Gemini APIキーの設定**(あなたの操作が必要)
1. https://aistudio.google.com/apikey でキーを作る(無料)
2. GitHub のリポジトリ → Settings → Secrets and variables → Actions → New repository secret
   名前 `GEMINI_API_KEY`、値にキーを貼る(**チャットやコードには書かない**)
3. Actions タブ → daily-kokugo → Run workflow で試す。結果は `data/last-run.json` に残る
- モデルは自動で選ばれる(固定したいときは Secret ではなく環境変数 `GEMINI_MODEL`)
- 無料枠では、送った内容が Google のモデル改善に使われうる。**送るのは漢字の一覧と問題文だけ**で、子どもの情報は送らない
- 手元で試す: `GEMINI_API_KEY=... node scripts/generate-kokugo.mjs --grades 2 --count 4`

## スマホごとの持ち主(ひびと/ゆいと)
- 最初の1回だけ「このスマホは だれの?」を選ぶ(その時に**パパのPIN**を決める)。以後は、その子の画面しか開かない。**相手の問題は開けない**(きょうだいの記録は見るだけ)。
- 持ち主の変更・「パパの へや」(右上の ⚙)には PIN が要る。PIN を忘れたら、ブラウザのサイトデータを消す(記録も消える)。
- 設定を楽にするリンク: 「パパの へや」→「きょうだいと つなぐ」で、子ども別のリンク(`#kid=hibito&db=…&fc=…`)をコピーできる。リンクを開くだけで、そのスマホの持ち主と共有設定が入る(持ち主が未設定のときだけ)。

## 理科・社会・生活(事実リスト方式)
- `data/know/*.json` に人が確かめた4択問題を置き、`node scripts/build-knowledge.mjs` で検査して `data/knowledge.json` にまとめる(アプリはこれを読む)
- 検査: 学年外の漢字は `{漢字|よみ}` のルビにしていないとエラー / 選択肢の重複 / 誤答ごとの「なぜ違うか(note)」が必須 / 1単元12問以上
- 偏りの検査: `node scripts/lint-knowledge.mjs`(正解が最長・最短の問題が多すぎないか)
- 追加の流れ: ファイルに問題を足す → `node scripts/build-knowledge.mjs` → `npm test` → コミット

## PIN(パパ用・子ども用)
- **PINの値は、コードにもGitHubにも書かない**(このリポジトリは公開のため)。各スマホの中にだけ、暗号のような形で保存される。
- **パパのPIN**: 「パパの へや」・持ち主の変更・PINの管理に必要。子ども用リンクで開いたスマホは、最初にパパがPINを決めるまで何も開けない。
- **子どものPIN**(任意): パパの へや →「🔐 PIN」で、ひびと/ゆいと別に設定。設定すると、その子の画面を開くたびにPINを聞かれる(右上の 🔒 でもロックできる)。
- **2人で1台を使うモード**: 「パパの へや」でオンにすると、最初に「だれが つかう?」を選び、本人のPINで開く。
- PINは**スマホごと**に設定する(3台なら3回)。忘れたら、ブラウザのサイトデータを消す(そのスマホの記録も消える)。

## ガチャ・選手・チーム・対戦(`game.js` = ルール、`ui-game.js` = 画面)
**チケットの もらいかた**(お金は一切つかわない)
- 勉強: 1セットで6割以上せいかい → ブロンズ1枚 / パーフェクト → シルバー1枚 / かくれステージ・タイムマシンはさらに+1枚。1日の上限は6枚
- ログインボーナス: 「連続」ではなく**通算の日数**(休んでも減らない)。3日目シルバー1、7日目シルバー2、14日目ゴールド1、30日目プラチナ1+ゴールド1(以後も7・14・30の倍数日)
- 最初に ブロンズ3 + シルバー1

**ガチャの確率**(ブロンズの場合): コモン60 / アンコモン28 / レア9.5 / スーパーレア2.48 / レジェンド0.02(%)。上位チケットほど低いレアが出ない(ブロンズ=なし、シルバー=アンコモン以上、ゴールド=レア以上、プラチナ=スーパーレア以上)。レジェンドは**チケットがいいほど出やすい**(ブロンズ0.02% / シルバー0.1% / ゴールド0.5% / プラチナ2%。最大2%)。選手は220人(コモン80・アンコモン60・レア44・スーパーレア24・レジェンド12)。**レア・スーパーレア・レジェンドの80人は、有名な選手を「モデル」にしたオリジナルのキャラクター**(名前はもじり。本人とは関係ない。国旗とタイプ=得意な動きつき。日本人モデルは21人)。コモン・アンコモンの140人は完全オリジナル。選手を足すときは**配列のうしろに足す**(選手IDと能力が変わらないよう、選手ごとに乱数を固定している。テストで固定値を確認)。実在の本名・クラブ名・写真は使わない。同じ選手がダブるとレベルアップ(最大Lv5、1つで能力+4%)。
**確率を変えたいとき**: `game.js` の `BASE_RATES` と `LEGEND_RATES`(テストが確率を検算する)

**強化**: 算数→シュート / 国語→パス / 理科→スピード / 社会→まもり / 生活→スタミナ。せいかい1つで+2pt。Lvが上がるほど必要ptが増える(1〜10Lvは1pt、11〜20Lvは2pt…)。強化値は `30 + Lv×1.5` で、**Lv47でレジェンドの最大(99)をこえる**。Lv100が上限。
**メダルのバフ**: メダルごとにチーム全体が% 強くなる。3つまで装備。上限+40%。
**対戦**: 11人(4-4-2: FW2・MF4・DF4・GK1)で、CPU(4段階)か、きょうだいのチーム(同じスマホか共有設定ずみのとき)と戦う。結果は運も入る(強いほうが勝ちやすい)。勝敗の景品はない(チケットは勉強とログインだけ)。

## 選手のイラスト(レア以上の80人)
- `images/players/*.webp`(320px・各約25KB)。Higgsfield(`gpt_image_2_5`)で作った、**タイプ・ポジション・レア度に合わせたデフォルメのオリジナルキャラ**。実在の人物の顔には似せていない(名前・顔・チームを指定せず、モチーフ=動物や道具だけで描き分け)。
- 画像が読み込めないときは、これまでの絵文字の顔に自動で戻る。コモン・アンコモンは絵文字のまま。
- 画像は `game.js` の `img` で指す。足すときは同じ名前(選手ID.webp)で `images/players/` に置く。
- ※ このリポジトリは公開設定。画像を公開したくないときは、リポジトリを非公開にするか、画像をコミットしない運用にする。
